中转站是什么，为什么有人用它

直接用 OpenAI、Anthropic 这些官方接口，你要先绑定海外信用卡或 PayPal，账号还可能因为地区、支付方式或使用习惯被风控限制。中转站做的事情很简单：先由中转站自己完成官方账号和支付的搭建，再把调用能力按份转卖给用户。你拿到的是一个和官方协议兼容的接口地址（base_url）加一个令牌，代码基本不用改。

对个人开发者来说，中转站解决的是"支付和网络门槛"；对企业来说，中转站还额外提供了额度管理、多模型切换和成本核算的后台，方便团队统一管控用量。

newapi / sub2api / CPA 三类程序的区别

市面上绝大多数中转站，不管界面做得多花哨，底层跑的基本是这三类程序之一，或者是在它们基础上改的皮。

newapi：按官方 API 额度分发

newapi 是从早期的 oneapi 项目发展出来的，核心思路是"渠道方买官方 API 额度，再按规则分给用户"。中转站在后台设置好每个模型的倍率、用户额度上限、可用模型范围，用户消费多少就从额度里扣多少。它本质上是一层计费与路由网关，谁在后面接的是官方 API、还是别的中转，前端用户通常看不出来。

sub2api：把订阅拆开分发

newapi 分发的是 API 额度，而 sub2api 分发的是订阅制账号（比如 ChatGPT Plus/Pro 这类按月付费、不按 token 计费的订阅）。可以理解成中转站团购了几份订阅，然后把里面的用量切成小份卖给很多人用。因为订阅账号本身有并发和频率限制，sub2api 除了转发请求，还要做账号轮换、限流和防止触发官方风控，这部分工作量比 newapi 大得多。

CPA（CLI Proxy API）：从命令行工具里取号

CPA 同样是从订阅账号取用量，但取的渠道是 Claude Code、Codex CLI 这类命令行工具背后挂的订阅额度，而不是网页版订阅。它做的封装和计费能力都比较轻，更常见于拼车、自用分享这类小范围场景，很少见到成熟的商业计费系统。

简化理解：newapi 转发的是"按量计费的官方 API"，sub2api 转发的是"网页订阅"，CPA 转发的是"命令行工具背后的订阅"。三者可以叠加使用，比如一个站点前台用 newapi 做计费和分发，后端上游接的是别人用 sub2api 或 CPA 转出来的账号池。

中转站的服务器和网络怎么选

中转站的稳定性，很大程度取决于它用什么线路、什么规格的服务器。了解这些，能帮你大致判断一个站点是"随手搭的小作坊"还是"认真长期运营的团队"。

网络加速方案

  • Cloudflare：最常见的免费 CDN，有技术能力的站点会再叠加优选 IP 给亚太用户加速。
  • 亚太 CDN：不少中小型服务商会走日本、香港节点，对国内的访问速度通常不错。
  • 备案后的国内 CDN：比如支持动态加速的国内厂商方案，速度更快，但要求域名完成大陆备案，合规成本和风险都更高，所以大部分服务商不会走这条路。

服务器规格

小型站点或者自用/分享给朋友的场景，一台普通 VPS（一年几百元档）基本够用。真正做到有一定用户量的站点，通常会换成带宽更大的独立服务器，因为中转站的负载模式是"高并发、吃单核性能"，而不是吃核心数量，所以选服务器时优先看单核性能和带宽吞吐，而不是核心数字。做大规模商业化的站点，一年的服务器成本可能在数千元甚至更高。

计费原理：额度、倍率和真实成本

这一部分是最容易让人看晕的地方：为什么同样的模型，不同中转站报价能差好几倍？先讲清楚几个概念，再看一个简化的例子。

记账单位不是真的美元

大部分中转站会把"1 美元官方标价额度"记成"1 元人民币平台额度"，方便计算，但这只是记账方式，不代表站点真的用 1 元人民币换到了 1 美元的官方余额。

倍率是怎么来的

假设中转站拿到一个订阅账号，成本是每月 1400 元左右，这个订阅账号一周能跑出的用量，按官方 API 标价折算大约值 1600 美元。按月折算：

1600 美元/周 × 4 周 ≈ 6400（元）平台额度/月
真实成本 1400 元 ÷ 折算额度 6400 元 ≈ 0.22

也就是说，光从"折算额度"和"真实成本"的比例看，倍率定在 0.2 左右才刚好不亏本。如果一个站点长期把倍率做到 0.1 甚至更低，那要么它的渠道成本比这个例子低很多，要么就是在用亏本价引流，不会长期持续。

看价格要看三层

判断一个报价是否合理，不能只看"折算后的官方标价额度"，要拆开看三件事：订阅或渠道的真实成本、这份成本能折算出多少官方标价额度、以及卖给用户时定的倍率。这三层分清楚，才能理解为什么有的站能做到 0.1～0.2 倍率还能维持，也能看出哪些价格低到不符合常理。

便宜渠道从哪来，风险点在哪

除了正常购买的订阅账号，市面上还流通着几类更便宜的渠道来源。了解它们是什么、为什么便宜，能帮你判断一个"骨折价"中转站背后可能承担着什么风险，而不是鼓励去操作这些渠道。

渠道类型是什么为什么便宜
平台优惠 / 首月折扣官方对新用户或特定地区给的订阅折扣官方补贴，用完即恢复原价，供给量有限
短期漏洞（俗称 Bug Team）官方系统偶发的计费或开户漏洞漏洞被发现前的窗口期，官方修复后立刻失效
争议支付找回（俗称黑冲）用户对第三方支付平台发起"未授权交易"申诉追回款项账号在同步封禁前还有几天可用窗口，本质是占用了支付纠纷机制，风险和道德争议都很高
第三方客户端逆向通过非官方 API 的客户端/IDE 间接获取模型访问绕开了官方计费入口，但接口不稳定、上下文容易被覆盖，输出质量通常打折扣
盗用密钥/余额搜集别人泄露或配置不当暴露的 API key完全不是渠道方自己的成本，属于侵占他人资源

越靠后的渠道，风险越大：涉及争议支付找回、盗用密钥的渠道本身就有法律和账号安全风险，作为用户即使自己没参与操作，也可能因为用了被截留数据的"投毒"上游而遭遇隐私泄露、模型被偷偷调包等问题。价格低到明显不合理时，先假设它用的是这类渠道，而不是"运气好"。

便宜渠道常见的副作用

  • 缓存命中率下降：如果后端账号池频繁更换或被封禁，你的对话缓存经常失效，实际计算成本反而更高。
  • 数据被二次利用：接入的账号如果本来就是别人的蜜罐或者监控目标，你的对话内容有被截留的风险。
  • 输出质量下降：通过第三方客户端逆向接入的渠道，往往自带一层固定上下文，容易和你自己的提示词冲突，导致回答变差。
  • 模型被偷偷替换：低价站点为了控制成本，有概率把请求路由到能力更弱的模型上，而不是你选的那一款。

六个常见坑和五条判断标准

把上面的原理落到实际选站上，可以归纳成两张清单：会踩的坑，和用来避坑的判断标准。

六个常见坑

  1. 套壳降配：宣传用的是旗舰模型，实际悄悄换成便宜的小模型或别人微调过的版本，回答质量和官网明显有差距。
  2. 黑盒计费：后台查不到每次请求真实消耗的 token，只看到余额在掉，扣得对不对无从验证。
  3. 低价引流后涨价或跑路：用远低于成本的价格吸引大量充值，充值高峰后涨价、限速甚至直接关站。
  4. 高峰期不稳定：平时正常，一到并发高峰就排队、超时，关键任务卡在中间最难受。
  5. 索要官方账号密码：正规接入只需要一个独立令牌，如果对方要你提供官方账号密码或邮箱验证码，账号安全已经不在你手里了。
  6. 充值容易提现难：充值时各种满减优惠，退款或提现时各种理由推脱，甚至设置余额到期清零逼你持续消费。

五条判断标准

维度靠谱的表现危险信号
模型是否纯血输出质量和官网一致回答明显变差，疑似降配或套壳
计费是否透明后台能查每次请求的 token 明细只显示余额变化，没有消耗明细
价格是否合理比官网便宜，但在前文倍率区间内低到明显不合常理，疑似引流或渠道有问题
付款是否方便且安全支付宝/微信/银行卡直接付，不涉及账号密码要求提供官方账号密码或验证码代为开通
运营是否稳定能查到成立时间、稳定的客服渠道，支持小额试用站点频繁更换域名，客服失联，没有历史可查

能同时满足这五条的站点，基本就在可以放心小额尝试的范围内了。

怎么用代码接入中转 API

只要中转站提供的是 OpenAI 兼容接口，接入方式和调用官方 API 几乎一样，改两个参数就行。

Python 示例

from openai import OpenAI

client = OpenAI(
    api_key="你的令牌",             # 中转站后台创建的 Token
    base_url="中转站提供的接口地址", # 换成任意一家中转即可
)

resp = client.chat.completions.create(
    model="模型名称",               # 以中转站文档列出的模型名为准
    messages=[{"role": "user", "content": "你好"}],
)
print(resp.choices[0].message.content)

curl 示例（快速验证令牌是否可用）

curl "中转站接口地址/chat/completions" \
  -H "Authorization: Bearer 你的令牌" \
  -H "Content-Type: application/json" \
  -d '{"model": "模型名称", "messages": [{"role": "user", "content": "hello"}]}'

如果主要是用 AI 写代码，很多中转站也提供一键配置文档，可以直接接进 Claude Code、Cline、Cursor 这类工具，不用自己写调用代码。

任何接入方式都只需要令牌，不需要你的官方账号密码。凡是要求账号密码或邮箱验证码"代开通"的，直接跳过。

想自己开一个中转站？

如果你也在考虑做中转，先想清楚自己的真实需求，再往下看基础设施和运营层面要注意的事。

先分清自用还是商业化

如果只是自己用量大，直接买官方订阅更省心，需要突破限制的操作留给自己账号做就好，没必要把自己的订阅拿出来分给一堆陌生人用。账号一旦出问题，追责和退款都会很麻烦。如果只是想和几个朋友拼车分摊成本，找现成的中转直接用即可，不必自己搭建。真正需要自己搭一套的，通常是想做规模化的商业站点。

上游怎么选

商业站点的上游无非两种：自己维护账号池，或者接现成的上游中转。自建账号池要面对账号被封的风险，需要提前做好并发控制和轮换策略；纯接上游则要承担上游不稳定、涨价甚至跑路的连带风险。很多站点是先接上游练手，摸清楚门道之后再逐步转向自建。

服务器和防护要点

  • 选服务器优先看单核性能和带宽，而不是核心数量，因为中转类程序的负载主要吃单核。
  • 选大厂、按固定带宽计费的机型，避免流量超额限速的坑。
  • 上线前一定先套上 CDN，不要暴露源站真实 IP，否则很容易成为同行或"练手"攻击者的目标。
  • 登录、注册接口和裸调 API 接口是最常被攻击的两个点，建议分别针对未授权请求做限流和拦截规则。

获客和支付

获客上，找到自己熟悉、目标用户集中的社区（比如面向开发者还是设计师）比广撒网更有效。支付渠道建议同时准备好国内扫码支付和跨境/加密货币支付，并且一定要留一个用户能找到人、能维权的沟通渠道，这也是前文"五条判断标准"里"运营稳定"对应的另一面：你自己作为运营方，同样要经得起这条标准的检验。

常见问题

中转站和官网直连有什么区别？

模型能力本身没有区别，前提是中转站给的是原版模型、没有偷偷降配。区别在于中转站帮你处理了海外支付、网络和账号风控这些麻烦事，价格通常也更低，但你需要自己判断平台是否靠谱，也失去了官方直接提供的售后保障。

中转站会不会突然跑路？

有可能，尤其是价格低到不正常的引流型站点。降低风险最实际的办法是不要一次充太多，先小额测试几天，确认计费和响应都正常，再决定要不要继续加值。

中转站的价格为什么能比官网便宜？

正规的低价通常来自批量采购、人民币结算省去的换汇和手续费成本，以及不同订阅渠道之间的价差。如果价格低到明显不合常理，大概率不是让利，而是用了前文提到的高风险渠道，或者模型被偷偷换成了便宜的小模型。

第一次用中转站，怎么用比较稳妥？

先按"五条判断标准"筛一遍，确认计费透明、能小额试用，再充值几美元或几十元人民币跑通一遍完整流程，确认输出质量和扣费都对得上，最后再考虑是否长期使用或大额充值。
